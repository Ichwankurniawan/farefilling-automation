WEB APP BASICS -- CHEAT SHEET
==============================

THE REQUEST PATH (memorize this chain)
---------------------------------------
Browser -> DNS -> nginx -> uvicorn -> FastAPI code -> your logic -> response back the same way

  DNS      Hostname -> IP address. Happens BEFORE any connection.
  nginx    The only thing listening on the real network. Routes by
           hostname to the right internal app. Where TLS/auth would
           go later.
  uvicorn  Runs your Python app, speaks raw HTTP, listens on a
           private port (127.0.0.1:xxxx).
  FastAPI  Your code -- defines routes (GET /, POST /api/jobs) and
           what each one does.


NETWORKING BASICS
------------------
  127.0.0.1 / localhost   "This machine only" -- loopback, never
                          reachable from outside. Same on every OS.

  0.0.0.0                 "Listen on every network interface" --
                          reachable from other machines. Avoid in
                          production; fine for local testing.

  Port                    A number identifying WHICH service on a
                          given IP. One port = one process at a time.
                          Pick any free one for internal use.

  Port 80 / 443           Convention for HTTP / HTTPS -- what browsers
                          assume if you don't type a port.


HTTP BASICS
------------
  Methods:
    GET   "Give me something." Safe to repeat, cacheable.
    POST  "Do something / create something."

  Status codes:
    200   OK
    400   Bad request (client sent something invalid)
    404   Not found
    409   Conflict / not ready yet
    429   Too many requests (rate limited)
    500   Server-side error


DEPLOYMENT BASICS
-------------------
  systemd service          Keeps your app running -- restarts on
                            crash, starts on boot.

  Reverse proxy (nginx)     Public door; multiple internal apps can
                            share one nginx on different ports.

  requirements.txt / venv   Pins exactly what Python packages your
                            app needs.


TESTING BASICS
----------------
  def test_something(self):
      # Arrange -- set up input
      # Act      -- call the real function
      # Assert   -- state exactly what must be true
      assert my_function(input) == expected

  Rules of thumb:
    - Test edge cases, not just the happy path -- that's where real
      bugs hide.
    - Name = the scenario, not the mechanism -- so a failure is
      understandable at a glance.
    - Unit tests = fast, isolated, no real files/network -- runs in
      CI on every push.
    - Integration/real-file tests = slower, closer to reality --
      catches what unit tests can't (the whole system together).

  Run it: pytest tests/ -v


Keep this handy -- every concept here transfers to basically any web
stack, not just this project.
